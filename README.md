# 报文邮局 · Packet Post

把网络协议拆开来读。每个数据包都是一封信，里面是**真实的字节**。

在线体验：<https://yongranliu.github.io/packet-post/>

9 个协议、26 个场景、138 个包，从一根网线走到一封邮件：
ARP → ICMP → UDP → TCP → DHCP → DNS → HTTP → TLS → SMTP。

## 运行

没有依赖，也不需要构建。ES Modules 不能从 `file://` 加载，所以要起一个静态服务器：

```bash
python3 -m http.server 8765
```

然后打开 <http://localhost:8765>。部署时把整个目录传到任意静态托管即可。

## 能做什么

- **拆信**：点任意一个包，逐层看 以太网 → IP → TCP → 应用层，字段和十六进制字节互相高亮。
- **沿途对比**：切换链路，看路由器和 NAT 改写了哪些字段，比如 MAC、TTL、校验和、源 IP、端口。
- **出事场景**：丢包重传、连接被拒、证书过期、ARP 欺骗、查无此人……不只有一切顺利的流程。
- **猜一猜**：寄出关键的包之前，先预测接下来会发生什么。
- **导出 pcap**：每个场景都能下载成 `.pcap`，直接用 Wireshark 打开。
- **集邮册**：走完主线得到一枚邮票，进度保存在浏览器里。

快捷键：`空格` 播放，`←` `→` 单步，`R` 回到开头，`V` 切换地图和时序，`O` 切换讲解和拆信，`1`–`4` 答题。

每个状态都有地址，比如 `#/tcp/fast-retransmit/8`，可以直接发给别人。

## 代码结构

```
js/net/        字节层：每层协议的真实编码、校验和、pcap 导出
js/world.js    世界模型：设备、路由，以及“包在第 N 段链路上长什么样”
js/protocols/  内容：每个协议一个文件，用 Script 写场景
js/ui/         地图、时序、日志、拆信、集邮册
js/app.js      状态和播放器
tests/         字节校验
```

全部界面都是 (协议, 场景, 游标) 的函数，播放、后退和深链接都只是在改游标。

一个包存的不是固定字节，而是生成函数：给定第几段链路，算出那一段的 MAC、TTL、NAT 地址和校验和。

### 增加一个场景

在 `js/protocols/` 里给协议的 `scenarios` 加一项：

```js
{
  id: 'my-case',
  title: '场景名',
  fault: true,                       // 故障场景，标签上有红点
  positions: { client: [100, 350], server: [885, 320] },
  intro: '开场白',
  build(s) {
    const c = s.tcpFlow({ path: ['client', 'server'], sport: 50000, dport: 80 });
    s.step('步骤标题', '讲解文字', [['事实', '值']]);
    s.ask('问题', ['选项 A', '选项 B'], 1, '解析');  // 问的是下一个包
    c.seg('a', { flags: ['SYN'], label: 'SYN', caption: '图注' });
    s.outro('收尾');
  },
}
```

序号、确认号、长度和校验和都是算出来的，不用手填。

## 验证

```bash
python3 tests/verify.py
```

需要 Chrome，有 `tcpdump` 时会多一层检查。它不信任 JS 的编码结果，而是：

- 用 Python 重算所有 IP、TCP、UDP、ICMP 校验和和长度字段
- 检查字段首尾相接地铺满每个包，没有说不清来历的字节
- 检查过路由器时 TTL 减 1、MAC 改变，只有 NAT 能改地址，交换机不改任何字节
- 回放 TCP 序号和确认号
- 检查 ICMP 差错引用的确实是原来那个包
- 把页面导出的 pcap 交给 `tcpdump` 解码

## 哪些是简化的

- 地址都是文档保留网段（`192.0.2.0/24` 等），根服务器和 `.com` 服务器的 IP 是真实的。
- 除了 TLS 的密文，字节都是可解析的真实格式。**密文是演示用的伪随机字节**，不是真的加密结果。
- 时间是模拟的，没有真的发包。
- 为了讲清楚，以太网帧没有补齐到最短长度，也没有 FCS，和在发送端抓包看到的一样。
